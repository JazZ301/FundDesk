# 数据来源与开源合规评估

本文评估 FundDesk（基金看板）公开到 GitHub 时，代码、行情数据和第三方内容的使用边界。结论基于 2026-11-27 对仓库代码、各数据源公开条款和 `robots.txt` 的检查，**不构成法律意见**。接口和条款会变化，正式商用前应让律师复核。

## 结论摘要

1. **代码可以开源**：业务代码是这个项目的自有实现；主要依赖是 MIT、Apache-2.0、BSD、MPL-2.0 等宽松或弱 copyleft 许可证，没有发现必须整库开源的 GPL-only 依赖。需要保留第三方许可证和声明。
2. **数据“公开可访问”不等于“可以自由再分发”**：基金净值、指数、板块、资金流、期货和基金经理简介都能在公开网页或接口中读取，但来源网站的条款普遍保留了著作权和数据库权利，部分接口还明确禁止自动访问。
3. **当前“本机运行时抓取、不托管数据”的架构是主要风险缓冲**：仓库不包含行情数据库，每个用户自己的电脑直接请求数据源，项目方不居中转售或批量分发数据。公开代码时应保持这一点。
4. **数据源已外置为配置项**：代码中不再写死东方财富、新浪、腾讯或 Yahoo 的地址；用户导入可信配置后才请求行情。Yahoo 默认为空，美股指数分时回退东方财富；默认 User-Agent 改为可识别的 `FundDeskDesktop/1.0`。
5. **个人本地使用风险较低，公开分发客户端的风险中等，商业化为高风险**：免费、开源、非商业的本地工具通常不是数据源重点追责对象，但“开源”不免除网站条款、著作权、商标和不正当竞争方面的义务。

## 1. 软件代码与许可证

### 1.1 自有代码

仓库内的 Rust、TypeScript、CSS 和构建脚本是本项目的业务实现，可以在你拥有版权的前提下选择开源许可证。当前仓库建议采用 MIT；如果希望限制他人把修改版做成闭源商业产品，可以改用 AGPL-3.0，但 AGPL 仍然是 OSI 认可的开源许可证，不能禁止商业使用。

### 1.2 第三方依赖

2026-11-27 用 `cargo metadata --locked` 和 `pnpm licenses list` 检查的主要结果：

| 依赖 | 许可证 | 说明 |
| --- | --- | --- |
| Tauri | MIT 或 Apache-2.0 | 桌面壳 |
| React / React DOM | MIT | 前端 |
| ECharts | Apache-2.0 | 图表；分发时应保留 NOTICE |
| zrender | BSD-3-Clause | ECharts 依赖 |

| `r-efi` | MIT 或 Apache-2.0 或 LGPL-2.1-or-later | 可选宽松许可，不是 GPL-only |

没有发现 GPL-only 依赖。MPL-2.0 组件（如 `cssparser`、`selectors`、`option-ext` 等）是文件级 copyleft：只要不修改这些文件，随二进制分发时保留许可证和来源说明即可；如果修改，需要公开被修改的 MPL 文件。

发布安装包时建议把 `THIRD_PARTY_NOTICES.md` 和主要依赖的许可证文本一起放进 DMG、安装目录或 Release 附件。仅靠 GitHub 源码仓库里的声明，不能完全替代二进制分发时的许可证附随义务。

### 2.2 robots 与条款的实际含义

- `robots.txt` 是爬虫约定，不是著作权法本身；但它是网站运营者表达访问意愿的证据。公开项目如果明确绕过 `Disallow`，在条款争议中不利。
- `Disallow: /` 不等于“数据绝对不能看”，但意味着自动化访问不受欢迎。个人浏览器正常查看与程序批量请求，法律评价可能不同。
- 东方财富法律声明明确提出：未经书面许可，不得复制、修改、转载、传播网站内容；未经交易所同意，不得复制、传播行情信息。
- 新浪知识产权声明保留网站内容版权，未经书面许可不得复制或镜像。
- 腾讯门户 `gu.qq.com` 的 robots 全站禁止；项目实际调用的 `qt.gtimg.cn`、`web.ifzq.gtimg.cn` 没有提供有效 robots，但仍受腾讯整体条款约束。Yahoo 的 robots 全站禁止，且其金融数据条款通常限制再分发。

这些条款主要约束“访问和再分发”，不当然禁止用户在自己的电脑上查看单条行情。项目应避免把自己做成数据聚合服务器或行情再分发平台。

### 2.3 社群配置不等于授权

把地址从软件里移到社群配置，**降低的是代码层面的固化风险，不会自动获得数据授权**：

- 如果社群分发的是未授权公开接口，访问条款和著作权风险仍然存在，只是由使用者和配置提供者承担更多。
- 如果社群分发的是公共代理、镜像或抓取服务，风险通常更高，因为项目方或群主可能被视为数据再分发者。
- 如果社群分发的是有正式授权的 API 地址，应同时说明授权范围、调用限额和是否允许再分发，不要把密钥写进公开配置。
- 配置文件是供应链的一部分。恶意地址可以返回错误净值或行情，进而误导投资判断。应用应只接受 HTTPS、显示配置来源、校验 URL，并避免把配置做成可执行代码。

因此，配置化是必要的工程能力，但不是“免责开关”。公开版仍应避免内置未授权地址，也不要把“必须加群”作为唯一入口；用户可以自行填写有授权的数据源。

## 3. “公开可用”到底是什么意思

### 3.1 可以直接做的

- 在代码中按用户操作实时请求公开接口，并只在本机缓存最近数据。
- 展示单只基金的净值、估值、披露持仓和少量指数行情。
- 在文档中引用数据来源名称、链接和截图，并注明“数据来自第三方，可能延迟或出错”。
- 让用户自己配置数据目录、刷新间隔和自选，不集中收集用户持仓。

### 3.2 不建议做的

- 把历史净值、全部基金列表、板块资金流等批量数据打包进仓库或安装包。
- 搭建公共代理、镜像站、公开 API，替其他人转发数据。
- 把数据用于收费订阅、广告变现、量化交易信号售卖或其他商业产品。
- 移除来源标识，或使用东方财富、新浪、腾讯、Yahoo 的商标、Logo 暗示官方合作。
- 伪造账号、绕过登录/付费墙、破解签名或攻击接口。
- 把基金经理简介、头像、研报、新闻全文批量复制到自己的数据库或页面。

### 3.3 一句话判断

**“我在浏览器里能看到”只说明数据公开可访问；“我能不能把它复制、缓存、再分发、商用”要看网站条款、数据来源授权和具体使用方式。**

## 4. 侵权风险分类

### 4.1 著作权

- 网站的文章、图片、页面设计、经理简介、研报和数据库编排可能受著作权保护。
- 单条基金净值、指数点位等事实性数据通常不构成作品，但“大批量抓取并原样提供”可能涉及数据库或汇编作品。
- 本项目的风险主要不在代码，而在是否把第三方内容打包、镜像或批量再分发。

### 4.2 合同/网站条款

- 访问网站即可能被视为接受其法律声明；自动化访问、绕过 Referer/UA 限制、过高频率请求都可能构成违约或干扰。
- 当前默认使用可识别的 `FundDeskDesktop/1.0`，Referer 由数据源配置决定；但配置仍允许填写浏览器 UA，公开项目应提示用户不要用它绕过访问控制。

### 4.3 不正当竞争

- 如果项目提供与数据源实质替代的公共行情服务，或批量抓取形成竞争性产品，可能引发不正当竞争争议。
- 免费、开源、单机、非商业的工具通常风险较低；收费、托管、面向企业的高频服务风险显著上升。

### 4.4 商标与官方背书

- 不要在应用名称、图标、宣传语中使用东方财富、天天基金、新浪财经、腾讯、Yahoo 的商标或近似标识。
- 文中出现来源名称用于事实说明和归属，通常属于描述性使用；不要写成“官方合作”“官方数据”。
- 应用名「基金看板」是通用描述，但公开前仍建议做一次商标检索，避免与同类付费产品混淆。

### 4.5 金融合规

- MACD 评分、红利评分、推荐语和买卖点如果被包装成“荐股”“稳赚”“代客理财”，会带来证券投资咨询方面的合规风险。
- 文档和界面应持续使用“研究辅助”“不构成投资建议”“数据可能延迟或错误”等表述。
- 不要提供下单、代管账户、收益承诺或跟单功能。

### 4.6 个人信息

- 本项目不收集用户账号、身份证、银行卡或交易密码；持仓只在本机。
- 基金经理姓名、简介属于公开的职业信息，但批量复制简介仍有著作权风险；保持“按需获取、本机缓存、不集中存储”更稳妥。

## 5. 风险分级

| 场景 | 风险 | 说明 |
| --- | --- | --- |
| 个人在本机使用，低频刷新 | 低到中 | 仍需遵守网站条款；不要批量下载或公开转发数据 |
| GitHub 公开源码，用户各自运行 | 中 | 代码本身可控；接口条款、社群配置来源和可选 Yahoo 源是主要争议点 |
| 公开 Release 安装包，免费使用 | 中 | 与源码类似，但安装包分发面更广；需附许可证和免责声明 |
| 提供公共后端、代理或镜像 | 高 | 可能被视为数据再分发/替代服务 |
| 收费、广告、企业服务 | 高 | 需要正式的数据授权、法务审查和交易所许可 |
| 把数据打包进仓库或安装包 | 高 | 直接复制和再分发的证据最明显 |

## 7. 当前代码中需要特别说明的点

### 7.1 请求标识与 Referer

当前默认 User-Agent 是可识别的 `FundDeskDesktop/1.0`，不再是浏览器 UA。新浪、腾讯的 Referer 由数据源配置中的 `sina.finance`、`tencent.portal` 决定；如果配置为空，请求不会伪造 Referer。部分兼容接口可能因此不可用，这是有意的取舍。

配置仍允许用户填写浏览器 UA 以兼容特定镜像，但这属于用户自己的选择；文档明确不建议用它绕过登录、付费墙或访问控制。

### 7.2 Yahoo Finance

Yahoo 现在只在 `data-sources.json` 的 `yahoo.query1` 非空时才会请求，默认配置为空。美股指数分时会回退到东方财富。若社群配置重新启用 Yahoo，配置提供者应自行确认其条款允许该用途。

### 7.3 基金经理简介

应用展示的是接口返回的简介文本，不是头像或完整简历库；只在本机缓存 7 天。公开版应避免增加“导出全部经理简介”“批量下载基金经理资料”等功能。

### 7.4 截图和旧文档

`docs/screenshots/` 中的早期 P3 截图是开发验证记录，发布前应逐一检查是否仍包含真实持仓、个人路径或过期界面。面向用户的文档统一使用 `docs/guide/screenshots/` 的演示数据截图。
